A: @hook Anthropic ने MCP बनाया। Server stdio से चलाओ या HTTP से?
B: Interview में पूरा सवाल ये आता है: MCP server को stdio से चलाएँ या HTTP से, और कब कौन सा? | तुम्हारा जवाब: एक app, एक machine, तो stdio। | कई लोग या कई apps, तो HTTP। || तीन बातें हैं।
C: MCP यानी वो standard, जिससे AI app बाहर के tools से जुड़ती है। | Tool वाला हिस्सा MCP server है, और transport यानी दोनों के बात करने का रास्ता। || मान लो, ये example है, तुम्हारे editor को सिर्फ़ अपनी files पढ़नी हैं। | यहाँ HTTP लगाओगे तो server host करना पड़ेगा, address देना पड़ेगा, login बनाना पड़ेगा। | 1{एक} आदमी के लिए 3{तीन} extra काम।
D: पहली बात, stdio यानी program का सीधा input-output। | App खुद server को अपनी machine पर subprocess की तरह start करती है, यानी साथ चलने वाला छोटा program। | App stdin में input लिखती है, server stdout में output लौटाता है। | क्योंकि server सिर्फ़ उसी app का है, hosting और login की ज़रूरत नहीं।
E: दूसरी बात, HTTP यानी network पर बात करना। | Server अपना अलग process है, एक endpoint यानी एक address पर, और कई clients जुड़ते हैं। | मान लो, एक company का tickets server है और 50{fifty} agents उसे इस्तेमाल करते हैं। | सबको एक जगह चाहिए, इसलिए यहाँ HTTP।
F: तीसरी बात, HTTP में दरवाज़ा खुला है। | Origin check करो, यानी request किस website से आई। | Local चला रहे हो तो localhost पर bind करो, यानी बाहर से पहुँच नहीं। | और authentication लगाओ, वरना कोई भी तुम्हारे tools चला देगा।
H: Interview में बोलो: “stdio runs the server as a subprocess of one client, so it is private and needs no hosting. HTTP is for a shared or remote server, and there I validate Origin, bind to localhost, and add authentication.”
