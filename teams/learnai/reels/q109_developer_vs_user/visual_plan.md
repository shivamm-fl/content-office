# Visual plan: q109, developer vs user instruction (interviewer_asked, @ai.learnvora)

Idea in one line:
When developer and user instructions clash, the developer's wins by rank, but a prompt is not a lock, so a hard business rule (refund limit) is checked in backend code that can overrule the model's yes.
The picture that explains it with the sound off: a refund bot with a 500 limit and a customer asking for 2,000; a three-step ladder System > Developer > User; a real 5-line run where the model says Approved and the backend prints Approved: False; a gate in front of the payment.

Look: clean-reel (flat navy, gold accent; cyan = developer/neutral part, green = right, red = blocked or risky, violet = system/model). Header: AI ENGINEER INTERVIEW. EXAMPLE pill on the invented refund case; the code and its output are a real run (state/runs/q109_refund_run.py).
